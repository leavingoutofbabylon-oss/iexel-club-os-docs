# Glossary

**Last verified:** 2026-07-24

---

## Terms

**Activity Log** — The `activity_log` table and `ActivityLogger` service that records all significant Club OS operations with user, action, object type, object ID and message.

**Admin Surface** — The wp-admin pages registered under the `iexel-club-os` menu slug. Accessible to users with Club OS capabilities.

**Audience** — The set of people invited to an event, stored in `event_audience`. Built by `EventAudienceBuilder` from team membership.

**Billing Run** — An automated batch of invoice generation triggered by a billing schedule. Stored in `finance_billing_runs` and `finance_billing_run_items`.

**Billing Schedule** — A recurring billing configuration that defines frequency, audience and fee rule. Triggers billing runs via WP-Cron.

**Club ID** — A human-readable identifier assigned to each person (e.g. `IEXEL-001`). Generated by `ClubIdGenerator`.

**Coach Workspace** — The portal experience for users with the `iexel_coach` or `iexel_head_coach` role. Accessed at `/club-os/coach`.

**Committee Workspace** — The portal experience for committee members. Includes governance, projects and finance overview.

**Container** — The minimal singleton DI container (`app/core/Container/Container.php`) used by `Application` to manage core infrastructure services.

**Experience Role** — One of five portal roles: Parent, Player, Coach, Committee, Treasurer. Determined by `MemberExperienceService` from the user's linked Person roles.

**Fee Rule** — A named fee amount used by billing schedules to generate invoice line items.

**Formation Template** — A named set of position slots for a football format (5v5, 7v7, 9v9, 11v11). Used by the lineup builder.

**Kernel** — The service locator (`app/core/Kernel.php`) that provides lazy-initialised access to all domain services. Each request handler receives its own Kernel instance.

**Match Mode** — The live match operations surface for coaches. Provides lineup, state, score, goals, substitutions, incidents and undo.

**Member Portal** — The frontend surface at `/club-os/`. Provides role-based workspaces for parents, players, coaches, committee members and treasurers.

**Module** — A functional domain within Club OS, corresponding to a directory under `app/core/`. Defined in `ReleaseModuleInventory`.

**Person** — A record in the `people` table representing any individual associated with the club (player, parent, coach, etc.).

**Person Role** — A role assigned to a person in `person_roles` (e.g. `player`, `parent`, `coach`). Distinct from WordPress capabilities.

**Portal Route** — A URL pattern under `/club-os/` registered as a WordPress rewrite rule.

**Profile Switcher** — The UI component that allows users with multiple experience roles to switch between them.

**Provider** — A PHP class that queries the database and returns structured data for a dashboard widget. Named `*Provider` or `*DataProvider`.

**Release Readiness** — The admin page and service (`ReleaseReadinessService`) that checks all modules, capabilities, routes and schema against their inventories.

**Repository** — A PHP class responsible for database access for a specific entity. Named `*Repository`.

**Season** — A named time period (e.g. `2025/26`) that groups team assignments and events.

**Season Plan** — A generated proposal for team assignments in a new season, created by `SeasonPlanningService`.

**Service** — A PHP class that orchestrates business logic. Named `*Service`.

**Team Season** — A canonical link between a team and a season, stored in `team_seasons`.

**Treasurer Workspace** — The portal experience for the `iexel_club_treasurer` role. Provides full Finance workspace at `/club-os/finance/`.

**Upgrade Runner** — The `UpgradeRunner` class that executes sequential upgrade steps to install or migrate the database schema.

**Widget** — A PHP component class that renders a dashboard section. Named `*Widget`.

**WP-Cron** — WordPress's pseudo-cron system used by Club OS for scheduled communications and billing runs.
